# Onboarding credential delivery release gate

Run `python3 scripts/inspect-onboarding-release.py inspect` from this repository. It is read-only. It verifies the MAM n8n connection through `/Volumes/UG/MAM/opencode/n8n/scripts/verify.py` using only that project's `.env`, confirms expected HR Outlook and receipt-header credential identities across paginated listings, scans existing workflows for the intended name and webhook path, classifies project-list access, and checks the scoped MAM Vercel production project and four variable names. It never reads Vercel values, exports the API key, generates a shared secret, or creates a workflow.

**Project administration is unsupported by the current n8n license, not a missing key or demonstrated API scope:** the verified MAM instance returned HTTP 403 with `Your license does not allow for feat:projectRole:admin` for `GET /api/v1/projects`. Workflow and credential reads succeeded on the same REST configuration. This does not establish whether credential creation or workflow creation is available; no POST was attempted. Existing workflow details did not identify a project, so an exact project ownership/share target remains unverified. Do not infer a default/personal project, borrow another key/account, or run a project-create/share operation on this plan. A future supported REST route must verify the precise project association and credential visibility before any write. The Vercel production project is `ai-7033s-projects/mam-team-management-system`; all four `ONBOARDING_CREDENTIAL_*` entries were absent at inspection. Do not write them without a separately reviewed production operation.

`node scripts/prepare-onboarding-workflow.mjs <verified-credential-id> "MAM People Hub - Onboarding Webhook Header"` produces only a local workflow definition with `active: false` from the existing builder; it does **not** call n8n or Vercel, create a credential, stage a workflow, or authorize deployment. Supply an ID only after read-only verification of the exact dedicated credential in the MAM instance. Do not pipe its output into a POST while the project target is ambiguous. Re-run the inspector immediately before any future staging and fail closed on name/path or credential collisions; after an interrupted write, read back exact objects before retrying rather than creating duplicates.

A subsequent reviewed release step must use a fresh high-entropy secret outside Git, create a dedicated `httpHeaderAuth` credential with header `x-mam-onboarding-secret` through a supported, project-verified route, pass its returned ID/name into the builder, create exactly one inactive workflow, and read back its project, inactive state, nodes/credential references, path and settings. It must persist the same secret only in an approved MAM-only secret store/Keychain and in the explicitly scoped Vercel **Production** `ONBOARDING_CREDENTIAL_WEBHOOK_SECRET`; set `ONBOARDING_CREDENTIAL_WEBHOOK_ORIGIN`, `ONBOARDING_CREDENTIAL_WEBHOOK_URL`, and `ONBOARDING_CREDENTIAL_EMAIL_MODE=disabled` in that same environment. Each write requires exact readback; if a partial failure occurs, stop without generating a different secret or duplicating a credential/workflow. No workflow activation, live mode, real recipient test, or outbound mail is authorised by this gate. Activation and live mode need a separate final approval after prerequisite migration, scheduler and synthetic end-to-end verification.
