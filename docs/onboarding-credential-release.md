# Onboarding credential delivery release gate

Run `python3 scripts/inspect-onboarding-release.py inspect` from this repository. It is read-only. It verifies the MAM n8n connection through `/Volumes/UG/MAM/opencode/n8n/scripts/verify.py` using only that project's `.env`, confirms expected HR Outlook and receipt-header credential identities, scans existing workflows for the intended name and webhook path, checks project-list access, and checks the scoped MAM Vercel production project and four variable names. It never reads Vercel values, exports the API key, generates a shared secret, or creates a workflow.

**Blocked for write preparation:** the verified MAM n8n API returns HTTP 403 for `GET /api/v1/projects`. Existing workflows do not expose a project ID in their detail response. Thus an exact MAM project ID and access to create/share the new header credential and workflow in that project are not verified. A 403 is not evidence of an invalid API key; `scripts/verify.py`, workflow reads and credential reads succeed. Do not choose the default/personal project or another project by inference. A reviewed project-target verification and API permission route are required before building a mutating prepare command. The Vercel production project is `ai-7033s-projects/mam-team-management-system`; the four `ONBOARDING_CREDENTIAL_*` entries are absent as of this inspection. Do not write them until the n8n project boundary is resolved and the parent reviews the operation.

A subsequent reviewed release step must use a fresh high-entropy secret outside Git, create a dedicated `httpHeaderAuth` credential with header `x-mam-onboarding-secret` in the verified MAM n8n project, pass its returned ID/name into `buildOnboardingCredentialWorkflow`, create exactly one inactive workflow, and read back its project, inactive state, nodes/credential references, path and settings. It must persist the same secret only in the approved MAM n8n project's gitignored secret store/Keychain and in the explicitly scoped Vercel **Production** `ONBOARDING_CREDENTIAL_WEBHOOK_SECRET`; set `ONBOARDING_CREDENTIAL_WEBHOOK_ORIGIN`, `ONBOARDING_CREDENTIAL_WEBHOOK_URL`, and `ONBOARDING_CREDENTIAL_EMAIL_MODE=disabled` in that same environment. Each write requires exact readback; if a partial failure occurs, stop without generating a different secret or duplicating a credential/workflow. No workflow activation, live mode, real recipient test, or outbound mail is authorised by this gate. Activation and live mode need a separate final approval after prerequisite migration, scheduler and synthetic end-to-end verification.
