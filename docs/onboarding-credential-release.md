# Onboarding credential delivery — community personal-project staging

The verified MAM n8n REST key can read workflows and credentials. `GET /api/v1/projects` returns `403` because this community licence excludes `feat:projectRole:admin`; this is **not** a key failure or a prerequisite for staging. The supported n8n API creates credentials and workflows in the caller's default personal project when `projectId` is omitted. The POST routes have not been exercised in this release. Do not use a different company account or a project admin/share route.

From the dedicated worktree, first run read-only `python3 scripts/inspect-onboarding-release.py inspect`. After separate approval for the exact external staging scope, run `python3 scripts/stage-onboarding-community.py stage`. **Do not execute the staging command as part of a local code review.** The command re-runs `/Volumes/UG/MAM/opencode/n8n/scripts/verify.py`, uses only that project's private `.env` for connection and a fresh 48-byte onboarding secret, and creates the dedicated `httpHeaderAuth` credential (`MAM People Hub - Onboarding Webhook Header`, header `x-mam-onboarding-secret`) without `projectId`. It uses the existing workflow builder to create `MAM People Hub - Onboarding Credentials (Live)` with no activation field in its POST, then checks the exact inactive workflow nodes, edges, settings, credential references and webhook path on GET. No workflow execution, activation, real recipient test, or outbound mail occurs.

Vercel writes are restricted to **Production** in `ai-7033s-projects/mam-team-management-system`, verified by project ID and owner. The command sets `ONBOARDING_CREDENTIAL_EMAIL_MODE=disabled`, `ONBOARDING_CREDENTIAL_WEBHOOK_ORIGIN` to the verified HTTPS n8n origin, `ONBOARDING_CREDENTIAL_WEBHOOK_URL` to that origin plus `/webhook/mam-people-hub-onboarding-credentials-v1`, and the sensitive `ONBOARDING_CREDENTIAL_WEBHOOK_SECRET`. It reads back the exact variable names, target and non-secret values; Vercel does not return the sensitive value, so it cannot cryptographically confirm secret equality on retry. The n8n credential API also does not return the stored secret. These boundaries are tracked through private `.env` binding markers; if a write succeeds but binding/readback fails, stop for manual investigation rather than create a duplicate or replace a secret. Do not paste or log the secret, copy it to a different repository, or put it in Hermes profile storage. Ensure the n8n `.env` is mode 600 before staging. A new deployment may be needed before Production variables affect the running application; this command does not deploy.

The read-only inspector reports collisions as blockers, not a call for a new key. Staging never calls `/projects` and does not share the personal project. `POST /credentials` or `POST /workflows` may still be rejected by the actual n8n API; an error stops the run without guessing a fallback or activation. An existing unbound credential/workflow or mismatched production value likewise blocks before writes. Review the exact state before retrying an interrupted run. Activation and `live` mode remain separate, gated release decisions after prerequisite migration and synthetic end-to-end verification.
